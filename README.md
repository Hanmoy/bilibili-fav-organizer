# B站收藏整理台

> 一个运行在 Tampermonkey / Violentmonkey 上的油猴脚本：调用你自带的 AI 模型，把 B站收藏夹批量分类并自动移动到对应收藏夹，全程可预览、可中断、可回退。

## 它解决什么问题

B站收藏夹的典型状态是「收藏即吃灰」：几百上千条视频堆在默认收藏夹里，靠标题已经找不到想看的内容。手动整理一次要几小时，且新增收藏后很快又乱。

这个脚本把整理拆成三步：**AI 读标题给分类 → 你在预览里改 → 一键批量移动**。分类结果先落成可编辑的清单，确认之前不会动你的收藏夹。

## 核心功能

**分类引擎**

- **两阶段 AI 分类**：先让 AI 设计分类体系（阶段一），再逐条归类（阶段二）。每条都带 reason 字段，解释为什么归到这一类
- **规则优先**：内置关键词 / 正则规则先行匹配，命中即定型，减少 AI 调用与费用；规则支持在界面里行内编辑，带安全校验
- **弱模型可用**：增量模式会抓取 B站官方标签（`/x/tag/archive/tags`）作为分类强信号，混元、GLM 一类小模型也能稳定归类；抓取失败自动降级，不阻断流程
- **超大分类自动拆分**：单个分类超过 70 条时，可对子集做二次归类（默认关闭）
- **反馈闭环**：你在预览里手动改动的归类会被记录，沉淀为后续的规则候选

**两种整理模式**

| 模式 | 适用场景 | 行为 |
| --- | --- | --- |
| 增量分配 | 只选 1–2 个收藏夹、新增视频不多 | 归入已有收藏夹，不新建分类 |
| 全量整理 | 一整个杂乱的收藏夹 | 重新设计分类体系，允许新建收藏夹 |

**执行与安全**

- **预览可编辑**：改名、下拉切换分类、新建分类、删除分类，确认后才执行移动
- **移动进度条 + 断点续跑**：点「确认并移动」立即显示进度；中断、刷新、风控暂停后可从断点继续，不重复移动
- **真增量**：记录各源收藏夹的基准，下次只处理新收藏
- **跨夹去重**：检测同一视频的多个副本，可一键清理
- **分类清单导入 / 导出**：导出 Markdown 交给外部 AI 对话整理，再回导执行；也可用于跨浏览器迁移
- **配置备份**：导出含 AI 配置、分类规则与整理记录（出于安全考虑不含 API Key）

## 工作原理

```
收藏夹列表 ──▶ 规则匹配（命中即定型）
                  │
                  └─▶ 阶段一：AI 设计分类体系
                          │
                          └─▶ 阶段二：逐条归类（分批 + 多轮补充分类）
                                  │
                                  └─▶ 可编辑预览 ──▶ 确认 ──▶ 批量移动（可续跑）
```

阶段一与阶段二之间可选择暂停，让你先确认分类体系再继续，避免一次跑完几百条才发现分类粒度不对。

## 安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/) 或 [Violentmonkey](https://violentmonkey.github.io/)
2. 打开本仓库的 **Releases** 页面，下载最新版 `bilibili-fav-organizer.<版本>.user.js`
3. 将文件拖入扩展管理面板，或点击扩展的「安装新脚本」导入
4. 打开任意 B站页面，页面右下角会出现悬浮入口

> 仓库不提交构建产物（`dist/` 已在 `.gitignore` 中），发版时在 Releases 上传对应版本的 `.user.js`，保证下载到的始终是可用的单文件。

## 使用

1. 打开 B站收藏夹页面（`space.bilibili.com` 或任意 `bilibili.com` 页面）
2. 在「收藏夹总览」勾选要整理的收藏夹（可多选）
3. 选择「全量整理」或「增量分配」
4. 按需填写整理要求，例如「AI 相关的拆细一点」「不要出现『其他』类」
5. 确认分类体系 → 在预览里调整 → 点「确认并移动」，页面内实时显示进度

## AI 配置

脚本本身不内置任何模型和密钥，全部由你提供，兼容 OpenAI 格式的接口。

在设置页填写三项：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| API 地址 (baseUrl) | 兼容 OpenAI 的接口根地址 | `https://api.deepseek.com/v1` |
| API Key | 服务商密钥 | `sk-...` |
| 模型 | 模型标识 | `deepseek-chat` |

其他可调项：AI 辅助分类总开关、允许新建收藏夹、规则优先于 AI、阶段一后确认分类体系、超大分类自动拆分、AI 每批处理条数（建议 ≤50，批次越小弱模型越不容易漏输出）。

配置与整理记录保存在浏览器的用户脚本存储（GM storage）中，不会上传到除你配置的 AI 接口之外的任何服务。

## 隐私与数据

- 脚本只与 `api.bilibili.com`（读取收藏夹、打标签、移动）和你配置的 AI 接口通信
- API Key 仅存于本地 GM 存储，导出备份时会主动排除
- 无统计、无埋点、无远程配置

## 开发与构建

```bash
npm install
npm run dev      # 本地开发，热更新
npm run build    # tsc 类型检查 + vite 构建，产物输出到 dist/
```


## 已知限制

- **依赖 B站非公开接口**：接口路径与风控策略可能随时变化，脚本按「节流 + 重试 + 识别风控」处理，但不能保证长期稳定
- **批量移动有风险**：移动请求会真实改动收藏夹，首次使用建议先导出备份（B站自身也提供收藏夹导出），并先在少量视频上验证
- **AI 分类质量取决于模型**：小模型在大批量、长标题场景下可能漏输出，表现为部分视频落入「未分类」，可通过调小每批条数缓解
- 仅在桌面端 Chromium / Firefox 系浏览器验证，移动端浏览器未测试
